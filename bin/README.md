# workmode — 作業モード別テーマ切替

作業・業務の種類ごとに tmux のアクセント色と Ghostty の背景をまとめて切り替える。

## 狙い（なぜ効くのか）

色そのものの心理効果（赤=集中 等）は再現性が低く、あてにしない。狙うのは次の2つ:

1. **切替という能動的行為の儀式性** — コマンドを打ち画面が一斉に変わる1〜2秒が、
   タスクの区切り（事象境界）として機能し、前タスクへの注意残余を減らす。
2. **反復による条件付け** — 「その作業を始める→そのモードにする」を一貫して続けると、
   見た目が作業モード起動のトリガーになる。定着には数週間〜約66日の反復が必要。

期待値は「集中力が上がる」ではなく「タスクの区切りが付けやすくなる」程度に置く。

## 使い方

```sh
wm coding      # コーディング（niagara / 青）※基準状態
wm review      # レビュー（yellow / 黄）
wm research    # 調査（green / 緑）
wm writing     # 執筆（wisteria / 紫）
wm break       # 休憩（brown / 茶）※画像を消し休憩ガイドを表示
wm review -m   # 切替前に resume メモ（前タスクの「次の一手」を1行記録）
wm             # 現在のモードを表示（--status も同じ）
```

tmux からは `prefix + W`（= `Ctrl-j W`）でメニュー選択。

## break（休憩）モードについて

休憩の回復効果は再現性が高い（活力・疲労軽減）が、生産性の直接効果は弱い。
そのため break は「集中力ブースター」ではなく「回復と持続可能性の儀式」と位置づける。
- **タイマーで強制しない**。コミットやテスト通過など自然な区切りで自分で `wm break` する。
- 作業画像を消し（デタッチメント）、自然・運動系の休憩活動をランダム提示する。
- 受動的スクリーン継続（同じ画面で SNS）は回復が弱いので、離席を促す。

## 運用ルール（重要）

- **モード定義・色は最低8週間は凍結する**。頻繁に変えると手がかりの弁別性が壊れ、
  条件付けが定着しない。`ricing`（見た目いじり）が目的化しないための歯止め。
- **モードは増やさない**。5つは弁別性の上限に近い。プロジェクト別×モード別のような
  細分化は一貫性を壊すのでしない。
- 効果はすぐには出ない。同一ペアリングを数週間続けてから判断する。

## 構成

- `bin/workmode` — 本体。状態ファイル → tmux → Ghostty の順に伝播
- `bin/workmode-break` — break 時の休憩ガイド（popup 内で実行）
- `bin/workmode-memo` — resume メモ入力（popup 内で実行、日次メモに追記）
- `tmux/modes/*.conf` — モード別のアクセント色定義（5枚）
- `ghostty/images/<mode>/` — モード別背景画像
- `~/.config/workmode` — 現在モードの状態ファイル（自動生成）

## 技術メモ

- Ghostty は `SIGUSR2`（1.2.0+）で設定リロード。`background.conf` を書き換えてから通知。
- 画像リロードが既存サーフェスに即反映されない場合の保険として OSC 11 で背景色を即時変更
  （tmux の `allow-passthrough on` 経由）。
- 同一モードの再指定は no-op（起動時復元の二重適用を防ぐ冪等ガード）。
